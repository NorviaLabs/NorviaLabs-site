A control layer for every agent you run.

One gateway in the path of every agent action, ours or not, with four controls behind it: what agents may do, who signs off, what happened, and which credentials they hold.

Gateway

PLANNED

Every agent, one checkpoint.

The problem
Companies run several agents at once: coding assistants, internal agents, and the MCP servers they connect to. Each brings its own permission model, or none.
Why it's hard
The checkpoint has to understand tool calls from agents it didn't build, add almost no delay, and fail closed without blocking routine work.
In Forge today
forge-tools validates every tool call against a JSON schema before it executes. The gateway takes that check, and Guard's policy, to other agents.

Guard

IN DEVELOPMENT

What agents may do.

The problem
Agents that can run commands and call tools need limits on what they can reach: files, hosts, sockets, credentials, infrastructure.
Why it's hard
Rules written as instructions to the model fail open. Enforcement has to sit below the agent, where it can't be argued with, and still let routine work through without a prompt.
In Forge today
An OS sandbox under every agent shell command (Seatbelt on macOS, bubblewrap on Linux), per-host network egress rules, and access-control and approval policy on every tool call in forge-governance.

Approvals

PLANNED

Who signs off.

The problem
An agent that asks in a terminal only reaches the person at that terminal. Team work needs the right approver, wherever they are.
Why it's hard
An approval has to be quick enough not to stall the work, specific enough to judge, and recorded against the decision it unblocked.
Today
Forge pauses on ASK decisions in the terminal. Conclave holds anything that commits, pushes or sends until an approver signs off.

Audit

IN DEVELOPMENT

What actually happened.

The problem
After an agent acts, someone has to answer what it did, under which policy, and why it was allowed.
Why it's hard
A useful record keeps secrets out and still proves what happened, in what order, under which decision.
In Forge today
Redacted audit events (tool, arguments, decision, policy, duration) from forge-governance, and a durable SQLite event journal in forge-durable.

Identity

PLANNED

Credentials that expire.

The problem
Agents often run on a person's long-lived tokens, so they can reach far more than the task needs, for far longer.
Why it's hard
Credentials have to be scoped to one run, issued without slowing it, and revoked when it ends, across providers that each work differently.
