About

Why Norvia Labs exists

Norvia Labs is an open-source lab exploring developer tools and infrastructure for agentic software engineering.

The thesis

As AI agents become active participants in software development, engineering tooling will need better interfaces for execution, permissions, observability, contracts, provenance, auditability, and human oversight.

The agentic era is not short on demos. It is short on boring infrastructure that survives contact with production: governance that actually governs, identities that expire, loops that stop, contracts for systems agents call, and audits you can prove.

The active project is Forge, a terminal-native AI coding environment. Additional experiments explore governance, contracts, routing, and audit around agentic systems. Each project is an experiment with a clear question, a small surface area, and a public outcome — ship, learn, or archive.

What “experiment” means here

An experiment is not half-finished product marketing. It is:

  • A single sharp idea, stated before the code exists
  • MIT-licensed code and releases when there is code to ship
  • Measurable claims — no numbers, no recommendation
  • Permission to be wrong in public

How we work

Public by default. Design notes and dead ends stay visible when they help the next person.

One idea per repo. Composition beats monoliths. If two concerns fight for the same README, they should be two experiments.

Measure first. Latency, cost, failure modes — if we recommend a tool, we want numbers next to the claim.

Active vs queue

Experiments marked Active are shipping now. Today that is Forge: a terminal-native AI coding environment with a public repository and releases.

Experiments marked Queue are ideas the lab intends to explore — governance, contracts, routing, and audit for agentic systems. They are listed for transparency, not presented as products, and may change or be dropped.
