Teams of agents and people, with limits built in.

In practice

The Software Delivery Team takes a GitHub issue through implementation, independent testing, code review, a pull request, CI monitoring and merge. Each step has its own member: a software engineer, a test engineer, a code reviewer and a delivery engineer.

Limits built in

  • Runs can't spin. Every agent run is bounded.
  • Delegation is budgeted. When the budget is spent, delegation is refused instead of recursing.
  • Changes need an approver. Writing files, committing, pushing, opening or merging a pull request, and sending all wait for a person, unless the builder explicitly turns on autonomous execution.
  • People are members, not spectators. Human members approve, reject, request changes or supply input, and their decisions are recorded in the run.

Definitions, not code

An application is a definition: its members, their tools, the shared results and their schemas, the workflow of steps, the request form and the limits. The same definition runs from the command line, in Studio and over a REST API. In Studio, the canvas is the plan while you edit it and the run while it runs, and every run keeps the version of the definition it ran.

Evidence, not claims

Results are bound to real sources, commits, test runs and CI checks. Nothing is invented: no sources, files, usage or cost that weren't actually returned. Blockers and missing evidence are reported as such, and errors, denied actions and approval requirements are never hidden.

Your AI, not ours

Conclave runs on the setup already on your machine: the Codex CLI, OpenCode, or a local Ollama server. Authentication stays with that backend. Conclave never guesses a model name and never silently replaces the backend you chose.

Conclave is in active development and not yet publicly released. Everything on this page describes the current build. Ask for early access.
